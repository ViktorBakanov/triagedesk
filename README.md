# TriageDesk — Module 03

A rules-only ticket-triage prototype. It intentionally contains no model client or credentials: the purpose is to establish a measurable baseline and collect an evaluation set.

## Data

The Module 02 source export available in this repository contains routing timestamps only, not ticket content. Therefore `triage/data/` contains a **deterministic synthetic** replacement: 800 tickets and 20 account domains. It is generated by `triage/generate_synthetic_data.py` and is clearly separate from the Module 02 export.

## Run

```bash
export POSTGRES_PASSWORD='choose-a-local-password'
export GIT_SHA="$(git rev-parse --short HEAD)"
docker compose up --build
```

Open http://localhost:3000. The UI presents one ticket at a time, explains the rule match (or escalation), and records an Accept or Correct decision. Use `docker compose down` to stop it; the API prints the one-line scoreboard on exit.

## Architecture

- `triage/rules.py` defines the stable `Triager` interface and the `RulesTriager` baseline.
- `tickets`, `accounts`, and `suggestions` are initialised in PostgreSQL on API startup.
- The FastAPI service proposes rules and validates/stores decisions; Streamlit is only the agent queue.
- A correction stores both the original proposal and the corrected category, urgency, and team, plus decision latency in milliseconds.

Coverage is the percentage of decided tickets for which a rule fired. Accuracy against corrections is evaluated only over corrected records, so it remains `n/a` until an agent submits at least one correction.
